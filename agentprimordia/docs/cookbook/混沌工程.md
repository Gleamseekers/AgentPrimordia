# Cookbook: 混沌工程实验

本指南演示如何使用 AgentPrimordia 的混沌工程框架验证 Agent 系统韧性。

## 核心概念

混沌工程通过主动注入故障来验证系统在异常条件下的行为：

1. **定义实验**：设置稳态假设和故障参数
2. **注入故障**：通过 ChaosEngine 编排故障注入
3. **观测指标**：监控系统在故障下的表现
4. **验证假设**：判定系统是否满足韧性要求

## 快速开始

### LLM Provider 故障注入

```go
package main

import (
    "context"
    "fmt"
    "time"

    ap "github.com/Gleamseekers/AgentPrimordia/pkg"
    "github.com/Gleamseekers/AgentPrimordia/internal/chaos"
)

func main() {
    // 创建混沌引擎
    engine := chaos.NewChaosEngine()

    // 定义 LLM 503 故障
    fault := chaos.NewLLMHTTP503Fault(chaos.LLMFaultConfig{
        Duration:    10 * time.Second,
        AffectedModels: []string{"gpt-4"},
    })

    // 创建实验
    experiment := engine.NewExperiment("llm-failover-test")
    experiment.SetSteadyState(chaos.SteadyStateHypothesis{
        Metric:    "success_rate",
        Threshold: 0.95,
    })
    experiment.AddFault(fault)

    // 运行实验
    result, err := experiment.Run(context.Background())
    if err != nil {
        panic(err)
    }

    fmt.Printf("实验结果: %s\n", result.Status)
    fmt.Printf("稳态验证: %v\n", result.HypothesisVerified)
}
```

### 自定义故障注入器

```go
// 实现 FaultInjector 接口创建自定义故障
type LatencyInjector struct {
    delay time.Duration
}

func (l *LatencyInjector) Inject(ctx context.Context) error {
    // 在网络层添加延迟
    time.Sleep(l.delay)
    return nil
}

func (l *LatencyInjector) Cleanup(ctx context.Context) error {
    return nil // 恢复原始状态
}
```

### Soak + Chaos 联动测试

```go
// 长时间混沌注入 + 退化检测
runner := chaos.NewSoakChaosRunner(chaos.SoakConfig{
    Duration:       30 * time.Minute,
    FaultInterval:  2 * time.Minute,
    DegradationThreshold: 0.1, // 10% 退化即告警
})

report := runner.Run(ctx, engine)
fmt.Printf("退化检测: %v\n", report.DegradationDetected)
```

## 运行 E2E 测试

```bash
# LLM 故障转移（无需特权）
go test -tags=e2e -run TestE2E_Chaos_LLMProviderFailover -v ./internal/chaos/

# 网络分区（需 Linux + root）
go test -tags=e2e -run TestE2E_Chaos_NetworkPartition -v ./internal/chaos/

# Soak 测试（通过环境变量控制时长）
CHAOS_SOAK_DURATION=5m go test -tags=e2e -run TestE2E_Chaos_SoakIntegration -v ./internal/chaos/
```

## 最佳实践

- 在生产环境运行前，先在 staging 环境验证故障注入不会造成数据丢失
- 使用 `SoakChaosRunner` 进行长时间韧性验证
- 将稳态假设与 Prometheus 指标集成，实现自动化韧性回归测试
- 网络分区测试需要 Docker 特权容器，参见 `docs/guides/混沌端到端.md`
