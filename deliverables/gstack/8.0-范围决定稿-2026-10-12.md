## 〇、先纠正四个数字（v1/v2 路线图口径修正）

路线图 §四 与 v8.0 叙事的三个数字不成立，本决定稿按实测重写。**这不是修饰，是范围本身的偏差**——按错数字签署会导致维护者以为砍掉了半个 API 面，实际只砍掉四分之一强。

| # | 旧口径 | 实测 | 偏差原因 |
|---|---|---|---|
| 1 | 「承诺面砍半（185 → ~90 导出符号）」 | pkg 是 **1367 个导出符号**的厚 re-export 层；本批标记 **387 个 = 28.3% 符号** | 185 只是 `pkg/*.go` 顶层 `func` 计数且含测试文件；漏掉了 type 别名 / const / var / 方法集（方法集恰是 re-export 层的主体） |
| 2 | 「维护面（承诺/文档/SDK 同步）约减半」 | 文件维度 **16/39 = 41%**；符号维度 **28.3%**；行数维度见下 | 「减半」在文件维度接近成立（41%），在符号维度不成立（28.3%）。建议对外叙事统一用「约四成文件、约三成符号」 |
| 3 | 「LOC 不会显著下降」 | 16 个文件当前 **2376 行** = 标记前 **1598 行**纯 re-export 别名 + 本轮新增 **774 行** deprecation 注释（387 符号 × 2 行）。8.0 执行删除时这 2376 行从 `pkg/` 消失，但 `internal/` 里的实现一行不动 | 原判断方向对、口径糊：pkg 这 16 个文件是**纯别名层**（`type X = internal.X`，无函数体），删掉它们是真删行；仓库总 LOC 几乎不变是因为实现在 internal/ 早已存在。**8.0 的收益是 pkg 面从 2376 行降到 0（这 16 个文件整体删除），不是"框架变小"** |
| 4 | 逐文件估数（governance 40 / chaos 27 / realtime 13 / strategy 11 …） | governance **60** / chaos **56** / realtime **35** / strategy **25** / autonomy 34 / skills 32 / soak 27 / intelligence 37 / wasm 14 / marketplace 13 / reflection 12 / otel 12 / supervisor 11 / tool_learning 8 / debugger 8 / planning 族 3 | 估数来自顶层符号 grep，漏方法集与 const/var 组。以 `v8_cut_scope.txt` 为准（AST 实测，与 API 黄金快照同口径） |

> **结论**：8.0 买不到「框架变小」（仓库总 LOC 几乎不变——实现在 `internal/` 早已存在），买到的是 **`pkg/` 承诺面从这 16 个文件的 2376 行降到 0、符号面收缩约三成、破坏集中一次**。
