### 2.2 根因分析

**P2 EnhancedPlanner 反向显著（p=0.001，11:0）**——v7.2 最重要的发现：

- 规划器为每个任务生成多层 plan（6 层 × 4-9 subtasks），每层 subtask 又触发新的 LLMPlanner 递归分解
- 在 sensenova-flash-lite（弱模型）上：规划本身消耗大量 turns/token，递归规划深入业务细节（如"明确范围界定的边界条件"）偏离任务目标
- 多数 B 臂任务触发 600s 超时（`B=FAIL(600s)`），超时保护生效后仍全军覆没
- 根因：EnhancedPlanner 的递归分解策略与 ReAct 短程任务（25 turns 上限）根本冲突——规划开销 > 规划收益

**P4 工具智能正向趋势（+17.4pp，7:3）**：

- B 臂系统提示中"优先使用已有工具组合"降低了重复造轮子
- 未达显著主因：样本量 23 太小。按当前 7:3 的不一致对比例，若扩至 ~60 任务可望 p<0.05

**P5 多模态正向趋势（+13.0pp，4:1）**：

- sensenova-flash-lite 无原生 vision 能力（API 返回 Forbidden，p5-vision-check.txt），双臂实际都在跑纯文本
- B 臂的"观察视觉信息"提示仍带来 +13pp，可能来自 fixture 描述文本的额外上下文
- 真正的 vision A/B 需要多模态模型（如 GPT-4o / Claude）才能有效测试

**P1 世界模型打平（+4.3pp，1:0）**：

- 预期内：世界模型的价值在状态一致性（V7 §三回放断言准确率），不直接提升任务成功率
- P1 硬任务 A 臂仅 17.4%——任务对 flash-lite 确实够难，但两臂都在爬坡

## 5. 结论与下一步

按 v7.2 设计规格 §6 回退策略：A/B 未达标（4 命题均 p>0.05 或反向），但集成测试地板已全部通过，**v7.2.0-rc1 按计划发版**，A/B 数字如实记录作为 v7.3 证据基线。

1. **P2 反噬是 v7.3 的头号修复项**：EnhancedPlanner 需加规划预算（如规划 turns ≤ 总 turns 的 20%）、禁止递归分解超过 2 层、或仅在 ReAct 失败 N 次后才启用规划
2. **P4/P5 扩样重跑**：各扩至 ~60 任务，验证 +17pp/+13pp 趋势是否达显著
3. **P5 需真 vision 模型重测**：sensenova-flash-lite 无 vision 能力，结论仅覆盖"多模态提示"路径
4. **P1 维持现状**：世界模型价值在一致性验收口径，任务成功率本非其目标
