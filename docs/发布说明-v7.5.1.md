## 摘要

本版是 v7.5 线的**发布链路修正版**。v7.5.0 的功能与安全修复内容完整保留（见 §附录），本版的核心交付是**让 v7.5 首次真正可被安装、可被校验**：

- 修复 **v7.3.0 起历次 GitHub Release 无二进制资产**的根因
- 补全 6 个平台的交叉编译产物与校验和签名
- 恢复 Docker 构建上下文中的 `go.work`（monorepo 布局必需）
- 修正容器镜像的 cosign 签名目标（由 meta 步骤改引用 build 步骤 digest）
- 补齐 `go.sum` 中 pgvector 模块的完整哈希
- npm 发布在缺少 token 时优雅跳过并显式告警

## 发布链路修复明细

| # | 问题（历史缺陷） | 根因 | 修复 |
|---|-----------------|------|------|
| 1 | **Release 资产为 0（v7.3.0 起）** | `upload-artifact` 的 `path` 写 `ap-*`，但二进制在 `agentprimordia/` 子目录产出，路径不存在 → 触发 v4 默认的 `if-no-files-found: warn`，二进制静默未上传 | 路径改为 `agentprimordia/ap-<os>-<arch>*`，并显式设 `if-no-files-found: error` |
| 2 | **6 个平台二进制在组织阶段静默缺失** | `cp artifacts/binaries/**/* release-files/ \|\| true` —— `artifacts/binaries/**` 不存在该名产物，且 `\|\| true` 吞掉错误 | 改为 `find artifacts -type f -exec cp {} release-files/ \;`，去掉 `\|\| true` |
| 3 | **Docker 构建失败（monorepo 布局）** | 根 `.dockerignore` 未对齐仓库根 context 布局，`go.work` 相关路径处理不当 | 重写根 `.dockerignore`，`**/` 前缀匹配任意深度，恢复 `go.work` 可被 context 包含 |
| 4 | **镜像签名目标为空** | `cosign sign` 引用 `steps.meta.outputs.digest`，而 meta 步骤不产出 digest | 为 build 步骤加 `id: build`，改引用 `steps.build.outputs.digest` |
| 5 | **`go.sum` 缺 pgvector 完整哈希** | 模块路径迁移后哈希未补全 | 补全 `go.sum` / `go.work.sum` |
| 6 | **tag-release 版本比较失准** | 浅检出会漏最新 tag，导致重复打 tag 冲突 | `actions/checkout` 使用 `fetch-depth: 0`（完整 tag 历史） |
| 7 | **npm 发布在无 token 时硬失败** | 直接执行 `npm publish` | 新增 token 探测步骤，缺失时告警并跳过 |

## 校验发布产物

v7.5.1 起，Release 附带 6 个平台二进制、SHA256 校验和及其 cosign 签名、SBOM。建议安装前校验：

```bash
# 1) 校验二进制完整性
sha256sum -c checksums-sha256.txt

# 2) 校验校验和清单的签名（keyless）
cosign verify-blob \
  --certificate checksums-sha256.txt.pem \
  --signature   checksums-sha256.txt.sig \
  checksums-sha256.txt
```
