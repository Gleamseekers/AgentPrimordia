# AgentPrimordia v7.5.2 — 补丁版（Patch）

> **发布日期**: 2026-10-26（尚未打 tag；待 `release/v7.5.2` 分支 CI 取得 Go 侧回执后由 `tag-release.yml` 触发）
> **影响范围**: 门禁可信度修复（死门/孤儿门/A4 断言缺失）+ 文档与实测对账 + **shell 工具 jail 逃逸修复** + **A1 宿主边界断言加固** + `pkg` 补齐 DeepSeek 导出
> **向后兼容**: ⚠️ 补丁级——无 API 破坏、无依赖变更，但含**一处安全行为收紧**：`shell` 工具对相对路径由「形态不似绝对路径即跳过校验」改为「按生效 workdir 解析后再禁锢」，此前依赖 `../../` 逃逸 workdir 的用法会开始被拒。wasm 沙箱默认翻转与 GLM/Qwen 多模态重构**不列入本版**（见下「本版不包含项」）

## 摘要

v7.5.1 发布后对「门禁是否真的会红」做了一轮对抗性复核，发现并修复了**五类同源缺陷**——它们共同的特征是：CI 看起来是绿的，但绿的理由不是"没有缺陷"，而是"门禁从没真正检查过"：

1. **死门**：`make cover-check` 的覆盖率阈值判断恒真。根因是 Makefile 每条 recipe 行都是独立 shell，跨行声明的变量在下一行已丢失，判断式退化为 `[: -eq: unary operator expected` 后仍打印 OK。修复过程中又发现两种"伪绿"变体（测试失败但覆盖率照常打印、编译失败导致覆盖率为空被判 SKIP）并一并堵死。
2. **孤儿门**：`scripts/dual-line-recall-check.mjs`（S0-3 双线召回对账门）自落地起**全仓零消费者**——CI / Makefile / nightly / release 均无引用，对账结论只存在于人工批次里。
3. **断言缺失**：code 层沙箱断言 A4（零值配置回退）所在的 `wasm/` 模块此前无任何 CI job 覆盖；仓库根 `AGENTS.md` §2.3 要求「A1–A8 全部进 CI、失败即红」。
4. **禁锢有洞**：`shell` 工具的 workdir jail 只校验绝对路径形态，相对 `../../` 从受禁锢的 `cmd.Dir` 出发即可越界——jail 形同虚设。
5. **断言面名不副实**：A1（wazero 导入白名单）只枚举 2 个模块、且按精确等值匹配根包，换一条 `wazero/api` 子包导入路径就能整体绕过，而注释与文档均称"全量枚举"。

同时完成文档与实测的对账收敛（详见下文），并把版本真值推进到 7.5.2（`pkg/agent.go` `const Version` → `agentprimordia/VERSION` → TS `package.json` → Helm 镜像 tag/appVersion → `api-contract.json` 全链同步）。

## 修复（Fixed）

| 项 | 症状（修复前实测） | 修复 |
|----|------------------|------|
| `make cover-check` 死门 | `[: -eq: unary operator expected` 后仍输出 OK、退出码 0——覆盖率不达标也绿 | 阈值判断改为单条 recipe（`@` + 续行）shell 块：跨行变量不再丢失；① `go test` 退出码非 0 直接 FAIL（测试/编译失败即红）；② 覆盖率为空按 FAIL 处理（不再 SKIP）；③ 分层阈值 `internal/agent:80` / `internal/llm:65` / `pkg:65` 镜像 CI 口径 |
| A4 断言不进 CI | `wasm/runtime_boundary_test.go` 的 `TestA4_ZeroValueConfigFallback` 在 CI 中永不执行 | 新增 CI job `workspace-modules`：`wasm/` / `pgvector/` / `gateway/` 三模块 `go build ./...` + `go test -count=1 ./...`（`CGO_ENABLED=0`），`changes` 过滤器新增 `workspace` 输出 |
| S0-3 双线召回门零消费者 | 脚本可跑（绿）但没有任何流水线调用它；两侧夹具同步漂移时无人发现 | 接线进 CI（job `dual-line-recall`）与 Makefile（`make dual-line-recall`），并**先重跑两侧真臂再对账**，最后断言重生成结果与已提交夹具逐字节一致（夹具确定性） |
| 文档统计与实测漂移 | README/AGENTS/CONTRIBUTING 的 internal 包数、agent 子包口径混乱；`docs/发布说明-v7.5.1.md` 版本表与实证不符；`sdk/typescript/AGENTS.md` 版本仍写 7.3.0 | 统一口径并新增门禁锚点（见下） |
| 文档死链门漏扫 HTML 内嵌链接 | `scripts/check-docs-links.mjs` 只扫 `[text](path)` 语法；README 的架构图与"交互式架构图"入口写在 HTML 里（`<img src>` / `<a href>`），模块路径迁移后遗留 `github.com/Gleamseekers/...` 前缀导致 **README 首屏架构图与入口链接双双 404**，而门禁长期全绿（实测：3 条 HTML 内嵌相对链接中 2 条死链） | 门禁补扫 HTML `src`/`href`（同一套跳过规则），并修正 README 两处路径、版本徽标指向当前 CHANGELOG 线 |
| **shell 工具 jail 相对路径逃逸** | `looksLikeAbsolutePath` 只对"呈绝对路径形态"的 token 施禁，`cat ../../etc/passwd` 形态上不是绝对路径被**整条跳过**；而 `cmd.Dir` 恰是受禁锢的 workdir，相对路径从它出发即可越界——filesystem 的 rootDir jail 可被一句 `cat ../../etc/passwd` 废弃 | 以 `resolveWithinWorkdir` 取代形态判断：相对 token 按生效 workdir（缺省回退 `allowedWorkdirs[0]`）`filepath.Join`（内部 Clean，正确折叠 `..`）解析后再做前缀比对；`WithAllowedWorkdirs` 把允许集统一归一为绝对路径（调用方常传相对 RootDir `"."`，允许集混着相对路径会让 jail 内合法相对路径被误拒）；新增 `shell_security_test.go`（+144 行）双向固化"逃逸被拒"与"jail 内相对路径仍可用" |
| **A1 宿主边界断言名不副实** | `host_boundary_test.go` 注释称"全量枚举三个模块"，实际 `moduleRoots` 只含 2 个（主模块 + 根 `wasm`），pgvector/gateway/operator 全在扫描面之外；且 wazero 匹配为精确等值 `imp == "github.com/tetratelabs/wazero"`，任何包改 import `wazero/api`、`/sys`、`/internal/...` **即可绕过 A1**——这不是假设，主模块 `agentprimordia/wasm/sandbox.go` 实际导入的正是 wazero 与 wazero/api 两条路径 | `moduleRoots` 扩为 `go.work` 全部 use 模块；匹配器改为 `importsWazero()` 覆盖本体与全部子包，并新增 `TestA1_WazeroImportMatcher`（验证子包命中 + 同名前缀不误判）；静态扫描改为 fail-closed（grep 退出码非 0/1，即 grep 缺失或路径不可读，不再被当作"无违例"静默跳过） |
| `pkg` 缺 DeepSeek 构造器 | README 的「10+ LLM Provider」列出 DeepSeek，`internal/llm/deepseek_provider.go` 也早有 `NewDeepSeekProvider`，但 `pkg/llm.go` 从未 re-export——公共 API 无对应构造器，文档与可用面不一致 | `pkg/llm.go` 补齐 `NewDeepSeekProvider` 导出（纯扩展，不动任何既有签名），`api-contract.json` 同步该条目 |

## 未决项（诚实记录，不在本版范围内）

- **A1–A8 的触发面**：`test` job 覆盖 A1–A3/A5–A8 且失败即红，A4 已由本轮新增的 `workspace-modules` job 覆盖；但 A1–A8 仍挂在 `changes.outputs.go` 触发面上——纯 TS/文档 PR 不会跑 Go 安全断言。改无条件 job 会让每个文档 PR 都跑全量 Go 断言，成本/收益需维护者裁定（已列为 `docs/V7.5现状对账与V7.6目标.md` 的 G1 候选）。
