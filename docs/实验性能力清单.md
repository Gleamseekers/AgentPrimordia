> 1. 新增能力前，先在此清单登记目标状态（🟢真实接线 / 🟡部分 / 🔴空壳）；

## 三、待接线项：成本与前置风险

> 成本为工程量估计（人日），**标注了审计中发现的隐藏前置条件**——不要按"改一行"预期排期。

1. **工具学习器自动装配** — ✅ **已实现（v7.4）**
   - 采用的方案：不新增 `EpisodeQuerier`，而是以 `internal/memory` 两个后端**都已具备**的
     `Add + List(SessionID)` 作为适配能力（`memoryEpisodeStore` 接口），
     避免给 SQLite 后端引入 `MATCH ''` 这类不可靠的空查询语义。
   - 落点：`internal/agent/tool_learning_adapter.go`（Episode 互转 + metadata 过滤）、
     `WithToolLearner` 显式注入、`buildAgent` 自动装配；`pkg.WithToolLearner` 导出。
   - 判据：`TestToolLearningRecordedDuringRun`（端到端：真实执行工具后经验落库）
     + 适配器 metadata 过滤测试 + "能力不足不装配"测试。

2. **全链路关联存储默认构造** — ✅ **已实现（v7.4）**
   - retention：`CorrelationStore` 增加有界保留（`defaultMaxRecords=1000`，
     `WithMaxRecords(n)`，`Start` 时按插入顺序淘汰最旧；<=0 回退默认，杜绝意外无界）。
   - 装配：显式 `WithCorrelationStore` 优先；否则当 `Hooks/Tracer/Metrics/Events`
     任一非 nil 时自动构造。完全不开启可观测性时保持 nil，默认路径零额外开销。
   - 判据：retention 淘汰/刷新/非法上限回退测试 + Agent 侧自动装配/默认不装配/显式覆盖/有界性测试。

3. **OTel 端到端接线** — ✅ **已实现（v7.4）**
   - 生产构造点：`ap.TelemetryFromEnv()` 读取 `OTEL_EXPORTER_OTLP_ENDPOINT` /
     `AP_OTEL_ENABLED` / `OTEL_SERVICE_NAME` / `OTEL_EXPORTER_OTLP_HEADERS` /
     `AP_OTEL_EXPORT_INTERVAL`，构造 `TelemetryProvider`（traces + metrics）。
   - 接线：`ap start` 生成的 quickstart 项目启动时调用并 `ap.WithTelemetry(tp)` 注入 Agent，
     `defer tp.Shutdown()` 管理后台导出 goroutine；未配置时零开销（不构造）。
   - 证据：`pkg/otel_env_test.go` 端到端——env → Provider → Agent 运行 → `ExportNow()`
     → httptest 端点真实收到 `/v1/traces` 与 `/v1/metrics`；另生成项目编译并运行通过。
   - 顺带清理：删除死兼容层 `internal/otel/`（全仓 0 引用），规则文档同步。

4. **Studio 接真实引擎** — ✅ **已实现（v7.4）**
   - 装配：`cmd/studio/main.go` 的 `buildStudioHandler` 默认注入
     chaos/cluster/learning/marketplace/autonomy/skills/realtime 七个真实服务，`-demo` 回退。
   - 新增适配器：`adapters_real.go` 提供 cluster（真实 `ClusterManager` 只读状态）、
     marketplace（真实 `TemplateRegistry` 持久化检索 + 部署生命周期）、
     chaos（真实 `ChaosEngine` 流水线）。
   - **chaos 安全边界**：Studio HTTP 契约只带 `FaultType` 字符串，缺少注入目标/参数，
     故适配器以 `NoopFault` + `AlwaysMet` 稳态真实跑通引擎（校验/登记/稳态/结果/中止），
     **不做宿主机级故障注入**；高危注入需在 SDK 中以完整 `Experiment` 规格显式发起。
   - 判据：三个适配器单测 + 端到端装配测试（基础面板不再标 `X-Data-Source: demo`）+
     `-demo` 回退测试 + marketplace HTTP 端点接线测试。

5. **模板注册表持久化 + 远程协议** — ✅ **已实现（v7.4）**
   - 持久化：`TemplateStore` 接口 + `JSONFileStore`（标准库实现，临时文件 + rename 原子替换）；
     `NewTemplateRegistry(WithStore(...))` 构造自动加载，Register/Update/Unregister/Rate/Downloads 变更落盘。
     （`internal/persist` 无通用 KV/文档存储，故未采用，避免为持久化引入无谓耦合。）
   - 远程协议：`FetchCatalog` 复用 `internal/marketplace` 的 cosign（ECDSA P-256）验签，
     支持对象/裸数组目录，先全量校验再写入（无部分导入）。
   - 生产构造点：`ap marketplace catalog add|list|remove`，持久化于 `.ap-templates/registry.json`。
   - 判据：持久化往返/重启恢复/变更落盘测试 + 远程导入/验签通过/验签拒绝/非 200 测试
     + CLI 端到端（add 落盘 → 重启加载 → list → remove）。

6. **技能库持久化 + 入循环** — ✅ **已实现（v7.4）**
   - 持久化：`PersistStore` 接口 + `JSONFileStore`（标准库、原子替换）；`NewStore(WithPersistence(...))`
     构造自动加载，Save/Delete 落盘，`PersistError()` 暴露错误。
   - 入循环：`injectSkillGuidance` 在循环中匹配最后一条 user 消息，命中则把技能名/说明/步骤
     作为 system 上下文注入（`skill_context` 标记、幂等替换，与 `memory_context` 同机制）；
     未配置 Matcher 时默认路径零变更。
   - 生产构造点：`ap skill list/add/remove/verify` 均为真实实现，持久化于 `.ap-skills/skills.json`；
     `verify` 为静态校验（结构 + 安全扫描），不执行步骤。
   - 判据：持久化往返/重启恢复/缺失文件/内存模式 + 循环注入命中/未配置不注入/幂等
     + CLI 端到端（add 落盘 → 重启加载 → list → verify → remove）。

7. **自治 CLI 真实化** — ✅ **已实现（v7.4）**
   - 装配：`AutonomyRuntime` + `toolStepExecutor`（步骤描述按 `"<tool> <json-args>"` 约定映射到注册工具）
     + `jsonCheckpointStore`（JSON 文件、原子替换，`.ap-autonomy/checkpoints/<id>.json`）。
   - 命令：`run`（含 `--plan` 多步计划）、`list`、`status`、`resume`（复用检查点计划快照，
     `ReadySteps` 自动跳过已完成步骤）；完成态由 CLI 补写终态检查点（runtime 仅落盘 validated）。
   - 安全边界：默认仅注册无副作用的 `echo` 工具，**不提供 shell 直通**，避免自治目标沦为任意命令执行。
   - 判据：run 落盘并执行、list/status/resume、resume 跳过已完成步骤、未知工具必失败、--plan 多步执行。
