## 一、背景与问题

### 1.1 现状：世界 = 消息序列（代码证据）

v6.0 及以前，ReActAgent 的全部「世界状态」就是一条 `[]Message` 切片。证据（主模块路径省略 `agentprimordia/` 前缀）：

| # | 证据 | 位置 | 支撑论点 |
|---|------|------|---------|
| E1 | 循环体唯一状态参数是 `history []Message`：`func (a *ReActAgent) runLoop(ctx context.Context, history []Message, startTurn int, ...)` | `internal/agent/react_loop_core.go:32` | 主循环没有独立的世界状态结构体，世界即消息序列 |
| E2 | 每轮把裁剪后的历史转成 LLM 消息：`trimmedHistory := a.trimContext(history, 0)` → `llmMessages := convertToLLMMessages(trimmedHistory)` | `internal/agent/react_loop_core.go:129-130` | LLM 每轮看到的世界 = 裁剪后的文本消息投影 |
| E3 | 追加式更新：`history = append(history, assistantMsg)`；tool 执行结果也以消息形式回写（`executeToolCalls` 返回新 history） | `internal/agent/react_loop_core.go:275,278` | 世界的更新方式 = 文本追加，无结构化断言可证伪 |
| E4 | Run 入口构造 history：系统提示词 → 回读本会话历史消息 → 追加本次输入 | `internal/agent/react_loop_engine.go:187-198` | 跨轮世界连续性同样靠「回读文本消息」拼装 |
| E5 | 记忆与 RAG 均以文本注入 history：`injectMemoryContextAndFastPath`（长期记忆回读注入）、`ragRetrieveAndInject`（检索片段注入） | `internal/agent/react_loop_blocks.go:29-62,78-104` | 记忆是世界的文本投影而非状态层 |
| E6 | 上下文裁剪：默认滑动窗口 `defaultMaxHistoryMessages = 100`，超出时丢弃最旧消息（保留首条系统消息 + 最近 N-1 条） | `internal/agent/react_persist.go:202`（常量）、`:208`起（trimContext） | **截断**：长任务中世界事实被无条件丢弃，且丢弃不可追溯 |

### 1.2 现状：kill -9 后的恢复语义是「重放」，不是「续知」

| # | 证据 | 位置 | 支撑论点 |
|---|------|------|---------|
| E7 | 检查点消息结构只有 Role/Content 两个字段：`type CheckpointMessage struct { Role string; Content string }`——ToolCalls 与结构化状态不落盘 | `internal/persist/checkpoint.go:10-13` | 检查点是文本快照，不是世界状态快照 |
| E8 | `saveCheckpoint` 把 history 逐条转成上述文本结构；`AgentState` 除消息与计数外无世界字段 | `internal/agent/react_persist.go:164-198`；`internal/persist/checkpoint.go:24-34` | 恢复 = 重建文本消息序列 |
| E9 | 恢复路径从 `state.Messages` 重建 history（仅 Role/Content）后重入 runLoop | `internal/agent/react_lifecycle.go:128-135,205` | kill -9 后语义 = 用文本重放恢复，模型需从文本重新推断世界 |
| E10 | 计划级断点续跑只存子任务文本与结果：`CheckpointPlan{Subtasks, Completed, Results map[string]string, ...}`；中断的 running 子任务标记回 pending **重跑** | `internal/persist/checkpoint.go:36-51`；`internal/agent/react_lifecycle.go:197-203`；`internal/agent/strategy/plan_checkpoint.go:60-70`（注释明示「running 视作 pending——中断的子任务重跑」） | 断点续跑 = 子任务级重放；已完成子任务的**世界副作用**（文件/外部状态变化）无结构化记录可校验 |

### 1.3 问题归纳

1. **漂移**：世界事实只存在于消息文本中，长任务下随轮次累积矛盾却无从检测（无逐断言可证伪的状态载体；E1–E5）。
2. **截断**：滑动窗口无差别丢历史（E6），被丢弃事实在后续轮次既不可引用也不可恢复。
3. **幻觉因果**：行动→结果的因果链只是 assistant/tool 消息的文本并置（E3），模型对「哪个行动导致哪个结果」的解释无机制约束。
4. **恢复即重放**：kill -9 后从文本重建世界（E7–E10），重放成本高且副作用不可校验——此即 v6.1 要以 state-checkpoint 协议偿还的债务（路线图 §三「工程地板」）。

> 上述 1–4 是结构事实（代码可证），不是复测扣分结论。路线图初版曾把「复测失分于长程状态漂移」当立项证据，已被自审 ② 判定为推断冒充证据并删除（`docs/V7路线图.md` §三 立项证据 ③ 注记）；本提案不复用该说法。

### 1.4 目标 API 现状

WithWorldModel / WorldModel / world_model 在全仓（Go 主模块 internal+pkg、TS SDK `sdk/typescript/src`）grep 零命中（2026-08-31 核对）：该 API 为 v6.1 **拟新增**，本提案约束其接入方式与默认策略，不与任何既有导出冲突。双线定位已登记于 `docs/双线豁免矩阵.md` 弧线登记 #1（v6.1，状态=对等，`internal/agent/worldmodel/` ↔ `src/agent/worldmodel/`）。

## 二、提案正文：三段式默认策略

### 2.1 第一段——6.x 期：WithWorldModel() 显式 opt-in（v6.1–v6.x）

- v6.1 新增链式选项 `WithWorldModel()`（与既有 WithXxx 链式 API 同风格，参照 `pkg/agent.go` 导出面），**默认关闭**；不调用时现有默认行为零变更（铁律 7：向后兼容到 6.0）。
- `pkg/` 导出标注 `// Stability: Experimental`（pkg 侧现状惯例见 `pkg/wasm.go:1`），并进入 `agentprimordia/docs/版本规范.md` §实验性 API 清单——Experimental 允许次版本号不兼容变更（版本规范 :104-112 既有条款），为三段式留出演进空间。
- 世界模型内核落 `internal/agent/worldmodel/`（依赖方向不变：处于 agent 顶层之下，可消费 llm/memory/tools 等下层模块；修订文本见 §三.1）。
- runLoop 接入点与 E1–E3 逐点对应：状态图更新挂钩 assistantMsg 追加（E3）与 tool 结果回写（`executeToolCalls`，react_loop_core.go:278）；预演 gate 在 tool 执行前；回溯差异写失败库（复用 `internal/persist` FailureStore 记录通道，参照 `internal/agent/learning/feedback.go:126-136` 的失败入库路径）。

### 2.2 第二段——评价线默认开：nightly 真实门以 world-model 运行

- **评价线默认开 ≠ 用户侧默认开**。边界声明：
  - *评价线*指 CI/nightly 评测 harness 构造 agent 的方式（`.github/workflows/nightly.yml` 与 S0-1 真实评测基建，路线图 §二 S0-1）。nightly 自 v6.1 起以 WithWorldModel() 开启态跑全部基准（含 S0-2 冻结长程集 `docs/evals/long-horizon-v1.json`），产出真实分布证据；
  - *用户侧默认*指库的公共 API 缺省行为，6.x 内保持 opt-in 不变。
- 理由（三条）：
  1. **证据独立性**：真实分布证据不受 opt-in 影响（路线图 §三 治理裁决原文）；若评价线也等用户 opt-in，v7.0 翻默认决策将没有任何先行数据；
  2. **风险隔离**：评价线崩溃/退化只影响 nightly 报告，不触达用户会话语义；用户侧 6.x 零默认变更保证铁律 7；
  3. **迁移公平**：翻默认判据（§五）必须来自「开启态在冻结题面留出子集上的成绩」，评价线默认开使该数字自 v6.1 起逐月累积、可审计。
- 兜底：nightly 双臂对照保留——同一题面同时跑开启/关闭两臂，防止「评价线默认开」掩盖世界模型臂的回归（对照臂成本计入 §八实验预算，路线图 R2/§十）。

### 2.3 第三段——v7.0：随主版本重锁翻默认

- v7.0 将 world-model 缺省值翻为开启（`NewAgent()` 默认启用，`WithoutWorldModel()` 显式退出），属**破坏性变更**（缺省行为变更），按主版本执行；届时：
  - 按 `agentprimordia/docs/版本规范.md` §破坏性变更流程（:151-159）五步登记（修订文本见 §三.3）；
  - 列破坏性变更 + 迁移指南（路线图 §三 治理裁决原文；`ecosystem/docs/migration/` 落 v7 迁移指南，版本规范 :132 既有约定）；
  - 翻转决策依据 = v6.1 命题 1 在 S0-2 冻结长程集**留出子集**上的成绩（路线图 §八 任务 1：「世界模型按 v6.1 裁决翻默认（附留出集证据与迁移指南）」「翻转决策入版本规范.md 登记」）；
  - 不达标不翻：v7.0 保持 opt-in 并在 v7-deprecations.md 记录延迟原因（降级豁免格式见 §五.3）。

### 2.4 不属于本提案的变更

- 不修改 `docs/evals/` 任何题面与 `manifest.json`（R4 冻结纪律）；
- 不修改 `internal/governance` 策略 schema——世界模型暂不需要运行时策略字段；若 v6.1 实现期需要（如预演 gate 的策略开关），走独立评审；
- 不触碰 code 层释放（属 S0-4 另一份提案 `docs/提案-code层沙箱受控释放.md` 的范围，v6.3 开工门）。

## 四、风险与缓解

| 风险 | 具体机制（对照 §1 证据） | 检测手段 | 回滚路径 |
|------|------------------------|---------|---------|
| **状态漂移**（状态图与真实世界不一致） | 世界模型是新增旁路状态，更新依赖 hook 时序；断言过时即误导预演 | ① 断言一致性门（§三.2，CI 回归）；② 回放任务断言准确率按 V7 §三命题 2 口径（点估计 ≥90%、Wilson 下界 ≥82%）出 nightly 报告；③ 回溯差异率进 nightly 看板 | WithWorldModel() 关闭即回退纯消息路径——opt-in 期回滚 = 用户不开启；nightly 回滚 = 关闭态对照臂成绩即基线 |
| **截断放大**（状态图未覆盖而消息又被裁剪的事实成为盲区） | trimContext 滑动窗口默认 100 条（E6）不变；若状态图覆盖率虚高，被裁剪事实无兜底 | ① state→persist→recall 闭环覆盖 100%（确定性覆盖度指标，V7 §三命题 3，允许 100）；② 旧文本路径一致性抽样 ≥99%（同命题 3）——双指标互斥造假空间 | 覆盖度不达标时 nightly 切回关闭态臂跑基准，世界模型臂成绩不计入版本验收（R4：验收只认留出集，题面不改） |
| **幻觉因果**（预演把未验证的行动→结果对写入状态图） | 预演产出的是预测不是观测；若与观测混存，回溯失去可证伪性 | ① 预演态/观测态在状态图中强制分型（实现约束，入 §三.2 一致性门测试范围）；② 回溯差异全部落失败库（复用 feedback.go:126-136 失败入库通道）供人工审计 | 幻觉率超阈值（实现期在实验计划书预注册）→ 停用预演 gate、仅保留状态追踪（V7 §三「工程地板」的降级形态：状态图内核 + 回溯进失败库仍成立） |
