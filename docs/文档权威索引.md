# AgentPrimordia 文档权威索引

> **本文档是 AgentPrimordia 文档体系的"唯一权威入口"。**
> 仓库内现有 260+ 篇 Markdown，历史记录与当前事实混排；本文档明确"每个问题该信哪一篇"，
> 避免同一事实出现多个互相矛盾的说法。
>
> **维护约定**：新增"当前状态/当前版本"类文档时，必须在本表登记；纯历史记录请归入 §四。

---

## 一、版本真值（Single Source of Truth）

| 事实 | 唯一权威来源 | 说明 |
|------|--------------|------|
| 框架当前版本 | `agentprimordia/pkg/agent.go` 的 `const Version` | **机器可读的唯一真值**；发布 tag 由 `.github/workflows/tag-release.yml` 依此生成 |
| 版本信息摘要 | [`agentprimordia/docs/版本规范.md`](../agentprimordia/docs/版本规范.md) | 人类可读的权威摘要；其余文档的版本描述以它为准 |
| 各组件版本 | 上表 + `sdk/typescript/package.json`、`sdk/python/pyproject.toml`、`sdk/rust/Cargo.toml`、Helm `values.yaml`/`Chart.yaml` | 第二真值文件，必须与 `const Version` 一致 |

**自动化门（漂移即红）**：
- `scripts/version-check.sh` —— Go / TS / 版本规范.md 三者一致性
- `scripts/version-sync-check.mjs` —— 双语言 major + Helm 部署载体
- `scripts/doc-version-consistency.mjs` —— `const Version` 与 VERSION 文件、TS、Helm、CHANGELOG 文件名、
  各文档"当前版本"锚点、README 统计数字的全面对账

三条门均在 CI 的 `version-consistency` job（无条件运行）或 `cross-language-check` job 中执行。
**不要手工批量"修版本漂移"——先跑这些门，它会给出去向。**

## 五、已知的文档体系债务（待收敛）

本文档只做"登记 + 指明权威"，不做删除。以下债务仍需处理：

   全仓 23 组重复 basename。
2. **主文档未进构建**：`agentprimordia/docs/mkdocs.yml` 有完整 nav（~117 项）但 CI 不构建 mkdocs；
   CI 的 vitepress 只发布 `sdk/typescript/docs/`（19 篇），主模块 124 篇文档从未被构建校验。
3. **链接检查覆盖有限**：`scripts/check-docs-links.mjs` 仅查死链，不查版本与事实一致性。
4. **统计数字易腐化**：README 中的文件数/包数/测试数由 `doc-version-consistency.mjs` 兜底，
   新增文档引用数字时请一律走该门。

> 处理这些债务时，请保持"每删/并一篇文档，先在本索引登记去向"的纪律。
